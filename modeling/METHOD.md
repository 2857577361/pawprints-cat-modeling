# 当前猫咪建模技术与方法

本文是 0.3.2 的实际实现总结，可以作为其他 Agent 制作猫咪角色的方法参考。方法本身独立于《爪印》；源码是一个可运行的示例。通用执行顺序见 [WORKFLOW.md](WORKFLOW.md)，可直接复制的任务指令见 [AGENT-PROMPT.md](AGENT-PROMPT.md)。

## 技术组合与交付边界

**Three.js 实时渲染 + 授权基础模型改造 + 照片投射贴图 + 程序化毛发及五官 + 骨骼蒙皮与程序化 IK 动作。**

这套实现没有执行照片自动三维重建，也没有在 Blender 中分别雕刻两只猫。薯片和羊羊共用一套 Fripouille 衍生网格与骨架，差异来自形状参数、独立毛色贴图、毛发和五官材质。定制效果在加载时生成；`companion-cat.glb` 仍是基础资产，不是完整定制成品。当前相似度仍不足，尤其眼周、耳根、侧脸与口鼻过渡。

| 层 | 使用的技术 | 用途 |
| --- | --- | --- |
| 资产 | GLB / glTF、GLTFLoader、SkeletonUtils.clone | 加载基础网格、UV、骨架与表情，复制独立角色 |
| 形体 | JavaScript 顶点变形、平滑区域遮罩 | 调整脸颊、眼眶、耳朵、下巴、体宽及尾宽 |
| 曲面 | 两轮 Phong 切平面中点细分 | 平滑轮廓并插值 UV、骨骼权重和 morph |
| 花色 | Python、NumPy、Pillow、UV 三角形光栅化 | 将照片采样结果烘焙成每只猫的 2048² 贴图 |
| 毛发 | Three.js BufferGeometry、面积采样、弯曲细条带 | 创建随皮肤运动、取色一致的实时毛发 |
| 五官 | 程序化曲面、Catmull-Rom 曲线、TubeGeometry | 鼻革、鼻缘、鼻孔、人中、唇线和眼睑 |
| 眼睛 | GLSL、onBeforeCompile、MeshPhysicalMaterial | 虹膜、瞳孔、角膜清漆层与反射 |
| 动作 | 骨骼蒙皮、足端目标、两骨 IK、速度驱动步态 | 走路、奔跑、跳跃及分段尾巴响应 |
| 展示 | Three.js、Vite；Electron 桌面封装 | 世界交互、镜头与本地应用；不属于建模方法的必要依赖 |

## 1. 选基础资产并记录个体特征

示例使用 kenchoo 的 Bicolor Cat，基于 guillaume bolis 的 Fripouille，许可为 CC BY 4.0。使用与分发必须保留双作者署名和来源，详见 [ATTRIBUTION.md](../ATTRIBUTION.md)。

开始前记录每只猫的脸型、眼距、眼形、鼻色、耳形、体态、左右花斑、分区毛长和尾巴轮廓。正面照片画面左侧对应猫自身右侧。生活照受视角、光照与姿势影响，不应将照片像素直接当成精确尺寸。不可见区域写明推测。

复用另一种模型时，先重新确认朝向、单位、网格名称、骨名、UV、法线方向与静止姿态。本示例的 `Object_8`、骨骼名称和所有空间阈值都与当前资产有关，不能直接套到任意猫模型。

## 2. 形体调整与曲面细分

`src/cat.js` 的 `personalizeSurface` 根据顶点在静止坐标中的位置生成平滑权重，再局部改变宽度、高度和深度。身体与眼球使用对应的眼眶变形，避免单独修改脸部导致错位。

原始静止坐标存入 `coatPoint`，供后续花色定位、毛发分区与虹膜坐标使用。`src/cat-surface.js` 执行两轮 Phong 细分：将边中点投射到端点切平面，插值 UV、骨骼影响和表情数据。

**细分改善平滑度，不能创造正确的解剖结构。** 如果基础模型的眼眶和口鼻差异很大，需要单独雕刻头部并重拓扑。局部变形只能承担比例修正。

## 3. 照片花色烘焙

`scripts/bake-cat-coats.py` 使用 Python、NumPy 和 Pillow，在本地生成 `coat-shupian.png` 与 `coat-yangyang.png`。运行时身体与毛发共享相同贴图，眼睛与鼻革分开处理。

过程为：

1. 读取 GLB 中的顶点、UV、法线和三角形索引。
2. 将 UV 三角形光栅化到 2048 × 2048 像素，使用重心坐标恢复像素对应的表面位置。
3. 人工配准照片中的眼睛、鼻尖、额头等标志点，对前向脸部进行分段映射。
4. 排除照片中的眼球与鼻革，防止投射到皮肤上后出现“双眼”和重复鼻子。
5. 从照片采样身体、背部、腿部与尾巴毛色，使用区域遮罩拼接，适度修正亮度与偏色。
6. 分开处理耳壳与粉色耳内，清理接缝，扩展 UV 边缘 12 像素减少 mipmap 漏色。
7. 统计不同表面间的 UV 重叠，输出审计报告。

这属于**人工配准的照片投射及照片片段采样**。它不从照片估计真实三维几何，也没有进行相机标定或准确的固有色恢复。照片中残留光照、侧脸拉伸和不可见部位估计仍是限制。

脚本针对当前两只猫的照片构图硬编码了标志点和采样区域。给第三只猫使用时需要重新配准，不能只替换文件后声称已自动适配。

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install numpy Pillow
python scripts/bake-cat-coats.py \
  --reference-dir /absolute/path/to/numbered-references \
  --output-dir public/models \
  --audit-dir /absolute/path/to/bake-audit
```

当前脚本实际读取 `01.jpg`、`04.jpg`、`10.jpg`、`11.jpg` 和 `12.jpg`。这些编号指向本轮新参考照片，与 `public/seed/` 中旧相册照片的编号不是同一组。仓库带有烘焙结果；本轮新增原片未随本次同步加入。精确重烘焙需要对应原片，第三方使用自己的照片时必须改配准参数。审计报告列出的参考编号是版本记录，不能替代完整逐像素来源追踪。

## 4. 程序化实时毛发

`makeFurGeometry` 按三角形面积选择毛根，再用重心坐标插值位置、法线、UV、静止坐标和四项骨骼影响。

每根毛使用三段弯曲、逐渐变细的窄条带。脸部短毛、胸颊毛、耳毛、背毛和尾毛分别设置长度与方向；眼睛、鼻头和肉垫周围排除毛发。身体与毛根从同一 UV 贴图取色，每根毛沿长度保留毛根色。固定随机种子便于比较版本。

薯片约 115,000、羊羊约 72,000 个候选毛根，排除区域后实际数量更少。根据镜头距离缩小 drawRange，降低远景绘制量；顶点缓冲仍驻留内存，因此不能把它视为完整多级资产 LOD。

目前没有专业 Groom 引导曲线、逐根毛发碰撞或完整物理模拟。毛量并不等同于像不像，也不代表已经达到写实毛发品质。

## 5. 五官结构与眼睛材质

`src/cat-face.js` 在基础模型的绑定姿态空间构造细节，随后应用同一套头部变形：

- 鼻革使用圆润轮廓与径向曲面；鼻缘和鼻孔使用细曲线。
- 薯片使用深灰鼻革，羊羊使用粉色鼻革及深边。
- 人中与 Y 形唇线使用 Catmull-Rom 曲线和细管状几何。
- 上下眼睑使用独立细曲线，继承附近皮肤的骨骼影响与眨眼 morph。
- 旧嘴槽由局部浅曲面遮盖，边缘透明过渡。这是覆盖修补，尚未真正重建嘴部拓扑。

细节的每个顶点从附近头部表面转移骨骼权重，绑定同一 skeleton 与 bindMatrix，随头部运动。眼睑在渲染前同步身体的 morph 权重。简单邻近转移仍需观察穿插和眨眼，不应当作通用的解剖绑定工具。

眼睛由 `makeEyeMaterial` 单独处理：以源空间眼球位置计算虹膜坐标，生成黄绿色虹膜、细辐射纹、边缘暗环和小瞳孔，避免沿用原眼部贴图的黑瞳孔。使用物理材质清漆层与环境反射增加角膜光泽。此效果在运行代码中，不会由普通 GLB 导出自动保存。

耳朵通过原网格变形与贴图分区调整，并没有新建完整解剖耳壳。当前面部仍保留共享底模的卡通特征。

## 6. 骨骼、蒙皮和动作

`src/cat-skin.js` 修复原资产的跨部位影响，合并权重、保留最强四项并归一化。尾巴与左右后腿分别识别，避免低垂尾巴误归属后腿，以及后腿内侧被躯干拉出薄片。

`src/cat-motion.js` 将整体位置与骨骼姿态分开：

- 行走：四脚错开相位；支撑期固定落脚点，摆动期沿抬脚轨迹前移。
- 奔跑：改变脚组相位、步幅和腾空比例，配合脊柱起伏。
- 后腿：处理膝与跗关节的弯曲方向、后踝折叠和可达范围，减少粘连和翻折。
- 跳跃：应用控制整体高度曲线，骨骼配合收腿与落地姿态。
- 尾巴：根部较稳定，后段延迟响应并限制幅度。

这些是程序化动作，没有采集两只真实猫的动作捕捉数据。跳跃与尾巴也没有完整物理模拟。基础资产原动画主要用于静止表情和眨眼，不能把它误称为原生走跑动作。

## 7. 复用与交付

推荐顺序：参考整理 → 基础资产适配 → 无毛灰模 → 个体花色 → 五官材质 → 分区毛发 → 蒙皮和动作 → 独立查看器 → 多角度对照。

方法不需要相册、账号或 App 上传接口。用户将照片交给自己的 Agent，由 Agent 执行 [任务指令](AGENT-PROMPT.md)，交付可编辑源文件或生成脚本、真正可用的运行资产、独立查看器及已知问题记录。

若需要交付完整定制 GLB，应额外烘焙或转换 GLSL 材质、程序化毛发、五官和 IK 动画，并在第二个查看器打开验证。现有基础 GLB 不能冒充完成的定制导出。

当前主要瓶颈是头部结构。继续提高相似度，应分别制作每只猫的头部、眼眶、口鼻和耳根，再接回已有颈口、骨架、毛色与毛发。验收以照片对照和可转动的三维结果为准，不以毛根数量或截图精致程度代替。

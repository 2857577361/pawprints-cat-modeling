# 从自己的猫咪照片制作三维角色：通用 Agent 工作流

本流程只描述输入、制作步骤、交付物和验收标准，不依赖《爪印》、Electron 或特定服务。用户把照片与任务交给自己的 Agent，由 Agent 使用可用的建模工具完成。输出可以接入独立网页查看器、Blender、游戏引擎或其他应用。

## 一、说明目标和能力边界

开始前记录三个目标：角色要像哪只猫、最近需要看到什么细节、运行在什么设备上。没指定时，以桌面实时展示、可旋转缩放、能看清脸部花纹、能播放走跑跳为默认目标。

普通生活照片提供外观参考，不会自动给出完整三维结构。单张照片看不到的背部、另一侧脸和尾巴花纹应标记为“推测”，不能当成识别结果。照片取色、套用基础模型、自动生成粗模、多视角扫描和手工雕刻是不同方法，交付时说明实际采用了哪一种。

先检查 Agent 的工具：能否操作 Blender、执行脚本、查看渲染、导出资产、预览动画。若只有代码能力，可采用实时程序化定制；若具备 DCC 工具，则可以交付更便于精修和跨引擎复用的源工程。不要承诺工具做不到的结果。

## 二、准备参考照片

建议准备：正面、左侧、右侧、背面、全身站姿、尾巴，以及眼睛、鼻头和爪子的近照；可以附上走路与奔跑视频。不要要求用户为了数量重复上传相似照片，先用已有资料制作。

整理时保留原图，另外生成裁切参考图，并为每张图记录：

- 文件、拍摄视角、是否镜像、光线是否偏色。
- 能确认的特征及对应照片。
- 不确定或遮挡的区域。
- 接收/导入时间；拍摄时间未知时保持未知，不用导入时间代替。

正面照片画面左边对应动物自身右边。先约定坐标和左右含义，再画非对称花斑。不要对三花猫直接镜像贴图。

用 [cat-profile.json](templates/cat-profile.json) 记录脸型、耳形、眼距、口鼻、体长、胸围、腿粗、尾长、毛长和分区花纹。没有可测依据的数值保留 `null`，不要编造精确尺寸或品种结论。

## 三、选择基础资产

优先选择解剖结构适合目标猫、许可允许修改和分发、拓扑与骨架可检查的基础模型。基础模型圆脸/长脸、短毛/长毛、体态差异过大时，需要重新雕刻，不能靠加毛量掩盖。

本仓库提供了可选基础模型 `public/models/companion-cat.glb`，署名见根目录 `ATTRIBUTION.md`。不使用它也能执行本流程。

导入后先检查：

1. 模型单位、前方轴、上下轴、静止姿态与缩放。
2. 身体、眼睛、眼睑、口鼻和胡须是否分离；UV 和法线是否完整。
3. 骨架有没有前肩、后髋、膝、跗关节、踝、脚掌和尾骨。
4. 逐个转动骨骼：后腿只能影响对应腿，尾端不能受腿骨控制。
5. 原动画到底是静止、眨眼还是走跑；不能把静止动画改名当成走路。

建立 [asset-adapter.json](templates/asset-adapter.json)，记录网格、骨骼映射、UV 区域和坐标。不要把某个模型的网格名称、骨骼名字或空间阈值当成通用标准。

## 四、先塑形，再做花色

### 形体

先用灰色无毛材质，在正面、两侧、背面与俯视对照照片：

- 头骨宽高、脸颊、下颌和口鼻突出程度。
- 耳朵大小、位置、朝向、耳根厚度。
- 眼距、眼眶深度和眼睑，不用放大眼球代替塑形。
- 肩、胸、腹、骨盆、四肢和尾巴轮廓。

形体修改后检查眼球与眼睑是否错位、嘴角是否拉裂。细分只让轮廓平滑，不会创造正确解剖。先修主要比例，再加密网格。

### 花色

将毛色分成底色、条纹/斑块、白色区域、脸部不对称区域、尾巴、鼻头和肉垫。先在中性灯光下确定颜色，避免把照片的室内黄光直接当毛色。

可以选择两种实现：

- **UV 贴图**：按照片投射、清理接缝并手绘不可见区域。适合输出可移植的标准材质。
- **静止空间遮罩**：用身体静止坐标控制斑块和条纹。适合程序化参数调整，但导出到其他引擎时要烘焙或移植着色器。

身体与毛发必须引用同一套色区，不能出现皮肤是白色、毛发却是深色的边界。空间遮罩不能依赖随动作变化的世界坐标，否则花纹会游动。

## 五、毛发分区梳理

先制作少量引导毛流，再增加密度：脸颊向外下方、额头向后、胸口向下、背部向尾根、尾部沿尾巴方向。排除眼球、鼻头和肉垫，口鼻短毛不要遮住轮廓。

离线精修可使用 Blender Hair Curves。曲线根部需要与表面和 UV 建立稳定连接，变形顺序也要保持一致，参见 [Blender：Attach Hair Curves to Surface](https://docs.blender.org/manual/sl/latest/modeling/geometry_nodes/hair/utility/attach_hair_curves_to_surface.html)。

实时展示可使用弯曲锥形毛片：

1. 按网格三角形面积采样毛根。
2. 插值毛根 UV、法线、静止坐标和蒙皮权重。
3. 按区域设置长度、宽度、弯曲和毛流。
4. 毛发与身体共享骨架及绑定矩阵。
5. 固定随机种子，确保重建结果可以比较。
6. 使用近、中、远距离预算，记录实际显存与帧率。

这些方法不等于逐根毛发物理模拟。数量不是质量指标：先避免尖刺、遮眼、穿插和色差，再提高细节。

## 六、骨架与蒙皮

采用清晰的四肢链、连续脊柱与尾骨。将身体中线、腹部、左右腿和尾巴分别处理，并在过渡处平滑权重。

必须避免本案例实际遇到的问题：

- **后腿粘连**：内侧低处顶点残留躯干权重，一只脚抬起时拉出薄片。低处腿部要保持归属，腹部中线再平滑回归躯干。
- **尾巴被腿拉扯**：尾巴下垂后低于某个高度阈值，被错误分配到后腿。尾巴的判定不能只依赖高度。
- **对侧腿受影响**：检查左右骨骼权重和中线过渡，不只看脚掌是否分开。
- **骨骼复制串联**：多个角色必须有独立骨架；Three.js 示例采用 [SkeletonUtils.clone](https://threejs.org/docs/pages/module-SkeletonUtils.html)，几何与材质默认仍可能共享，修改和释放时要明确所有权。

对实时四权重实现，合并影响、保留最强四项并归一化。最终以目标引擎支持的权重数量为准。绑定矩阵、骨长和局部轴必须保持一致；复杂拓扑优先使用权重绘制，空间遮罩只是当前示例的修复方案。

## 七、走路、奔跑、跳跃和尾巴

可以使用手工关键帧、许可清楚的动作重定向，或程序化 IK。统一规定整体位移由谁负责，避免根运动和控制器同时推进角色。

### 足端与后腿

走路的四脚应错开相位。支撑期记录世界空间落脚点，摆动期沿抬脚轨迹移动；以实际位移推进动作，避免撞到障碍仍滑步。奔跑另设脚组相位、步幅、腾空和脊柱变化，不只加快走路播放。

后腿有膝关节与跗关节。抬脚时需要同步折叠后踝；固定的脚踝偏移可能把膝盖顶到髋部上方。使用稳定弯曲方向、可达范围、关节限制和左右足端通道。急转弯时限制旧速度预测出的落脚点；不能让脚跨过身体追逐失效目标。

跳跃至少分准备、蹬地、空中收腿、伸腿与落地缓冲；落地后重新建立支撑点，避免脚仍被锁在起跳位置。若只用了高度曲线，明确说明没有完整碰撞与落地物理。

### 尾巴

根部稳定，后续段逐渐延迟响应，幅度有上限。运动中的尾巴主要协助身体平衡，转弯可产生小幅反向摆动。避免每节同频同幅旋转导致累计扭曲，也不要把固定正弦摆动说成真实物理模拟。

每种动作都从侧面和背后检查，不能只看漂亮的正面截图。

## 八、交付和展示

通用交付建议：

```text
my-cat/
  references/              原图与参考视图
  cat-profile.json         特征、证据和推测项
  asset-adapter.json       资产坐标与骨骼适配
  source/                  可编辑工程或生成脚本
  exports/                 实际生成的 GLB、贴图等
  viewer/                  独立展示入口
  preview/                 多角度静帧、走跑跳视频
  ATTRIBUTION.md            素材来源、许可、修改
  ACCEPTANCE.md             已验证项目与已知问题
```

展示器只需要加载角色、可旋转缩放、切换动作和中性光照，不依赖相册、账号或资料管理。只有生成并验证过的文件才能放入 `exports/`，不要用原始基础模型冒充定制成品。

GLB 是运行资产，不一定保存源工程中的所有效果。自定义材质、程序化毛发与程序化 IK 需要烘焙、转换成支持的几何/动画或配套运行代码。Blender 的 [glTF 导出文档](https://docs.blender.org/manual/en/3.6/addons/import_export/scene_gltf2.html) 列出了可导出的动画类型与皮肤数据；实际导出时核对本机版本，并在第二个查看器中重新打开验证。

## 九、验收与迭代

使用 [ACCEPTANCE.md](ACCEPTANCE.md)。每轮固定镜头、灯光和姿势，把照片、上一版、当前版放在一起比较。先修脸型与花斑方向，再修毛流，最后增加细节。

Agent 最终报告应包含：实际方法、交付文件、运行方式、已完成检查、仍不像的部位和未验证项目。不能把“写了流程”说成“已建好猫”，也不能把一张渲染图说成可操作三维资产。
